# Сервис терминологии

Сервис для хранения справочников, их версий и элементов. Реализован на Django и Django REST Framework, база данных — SQLite.

Данные редактируются через административную панель на русском языке. REST API позволяет получить список справочников, элементы выбранной версии и проверить соответствие кода и значения.

## Запуск

Требуется Python 3.10 или новее.

Из папки проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser
python manage.py runserver
```

Для Windows вместо `source .venv/bin/activate`:

```powershell
.venv\Scripts\Activate.ps1
```

Команда `seed_demo` добавляет демонстрационные справочники медицинских специальностей и МКБ-10. Она необязательна: данные можно создать через административную панель.

После запуска доступны:

- Административная панель: http://127.0.0.1:8000/admin/
- Swagger: http://127.0.0.1:8000/api/docs/
- Схема OpenAPI: http://127.0.0.1:8000/api/schema/

Логин и пароль администратора задаются командой `createsuperuser`.

## API

| Запрос | Назначение |
| --- | --- |
| `GET /refbooks/` | Список всех справочников |
| `GET /refbooks/?date=2022-10-01` | Справочники, имеющие версию, действующую на указанную дату |
| `GET /refbooks/{id}/elements` | Элементы текущей версии |
| `GET /refbooks/{id}/elements?version=1.0` | Элементы указанной версии |
| `GET /refbooks/{id}/check_element?code=1&value=Врач-терапевт` | Проверка элемента в текущей версии |

Для проверки элемента можно дополнительно передать `version`.

Текущая версия определяется по максимальной дате начала действия, не превышающей сегодняшнюю дату. Будущие версии автоматически не выбираются, но доступны при явном указании `version`.

Проверка возвращает:

```json
{"valid": true}
```

Если в выбранной версии нет элемента с такой парой кода и значения:

```json
{"valid": false}
```

Сравнение точное: регистр и пробелы учитываются. Все методы и примеры доступны в Swagger.

## Административная панель

Поддерживаются создание, изменение и удаление справочников, версий и элементов.

На странице справочника можно редактировать его версии, а на странице версии — её элементы. В списке справочников отображаются текущая версия и дата начала её действия.

Ограничения уникальности справочников, версий, дат и кодов элементов реализованы на уровне базы данных.

## Проверки

Запуск тестов:

```bash
python manage.py test -v 2
```

Проверка конфигурации и миграций:

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
```

Генерация и проверка схемы OpenAPI:

```bash
python manage.py spectacular --file schema.yaml --validate --fail-on-warn
```

Тесты покрывают API, выбор текущей версии, фильтрацию по дате, проверку элементов, обработку ошибок, ограничения уникальности и основные страницы административной панели.

## Принятые решения

Некоторые детали в ТЗ не определены однозначно:

- В ответе списка справочников возвращаются `id`, `code` и `name`, как в примере ТЗ. `id` — строковое представление идентификатора записи.
- Для проверки элемента выбран ответ с булевым полем `valid`.
- Дата начала действия допускает отсутствие значения, поскольку в ТЗ она не отмечена обязательной. Такая версия доступна по явному номеру, но не выбирается текущей. Несколько версий без даты допускаются.
- Отсутствие справочника или нужной версии возвращает `404`. Существующая версия без элементов возвращает пустой список.
- Некорректные или пустые параметры возвращают `400`.
- Для определения сегодняшней даты используется часовой пояс `Europe/Moscow`.

## Локальная конфигурация

По умолчанию включён режим разработки. База данных создаётся при выполнении миграций и не хранится в репозитории.

Настройки можно передать через переменные окружения: `DJANGO_DEBUG`, `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`. При отключении режима разработки необходимо задать собственный секретный ключ.
